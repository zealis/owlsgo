# owlsgo 插件开发规范

本文档面向插件作者，描述owlsgo 的插件清单格式、生命周期、可用 API、真实钩子清单与安全边界。

配合阅读：`plugins/owlsgo-demo/` —— 一个可直接启用、覆盖全部主要能力的示例插件。

---

## 一、快速开始：最小插件

```
plugins/my-plugin/
├── plugin.json
└── Plugin.php
```

`plugin.json`

```json
{
    "name": "我的插件",
    "version": "1.0.0",
    "description": "一句话说明这个插件做什么。",
    "author": "你的名字",
    "namespace": "MyPlugin",
    "entry": "Plugin.php",
    "requires": "1.0.0"
}
```

`Plugin.php`

```php
<?php

declare(strict_types=1);

namespace MyPlugin;

use Core\Plugin as PluginApi;

final class Plugin
{
    public static function register(): void
    {
        PluginApi::filter('content_rendered', static function (string $html): string {
            return $html . '<p>—— 本文由我的插件处理</p>';
        });
    }
}
```

放到 `plugins/` 下，进入后台 **插件管理**，列表中会出现「我的插件」，点击 **启用** 即可生效。

> 关键约定：入口类名固定为 `{namespace}\Plugin`，并必须提供 `public static function register(): void`。
> `register()` 在**每个请求的应用引导阶段**都会执行，因此只允许「注册」，不允许查询数据库、输出内容或做重活。

## 二、目录结构约定

| 路径 | 作用 |
| --- | --- |
| `plugin.json` | 清单：元数据、钩子声明、静态资源、配置项 |
| `Plugin.php` | 入口：注册自动加载 + `register()` 登记能力 |
| `register.php` | 可选。若存在，会在入口类 `register()` 之后被 `require`，适合纯函数式插件 |
| `Service.php` / 其它类 | 业务逻辑（自行注册 PSR-4 自动加载） |
| `sql/sqlite.sql`、`sql/mysql.sql`、`sql/pgsql.sql` | 启用插件时按当前引擎自动执行 |
| `assets/*` | 静态资源，合并后经 `/plugin-assets/{type}` 输出 |
| `templates/*.php` | 插件自带模板，用 `view('plugin/{id}/xxx')` 渲染 |

## 三、`plugin.json` 字段说明

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | string | 建议 | 后台显示名。缺省回落到插件 ID |
| `version` | string | 建议 | 默认 `1.0.0` |
| `description` | string | 建议 | 后台列表与插件页展示 |
| `author` | string | 否 | 作者 |
| `url` | string | 否 | 插件主页 |
| `entry` | string | 否 | 入口文件，默认 `Plugin.php` |
| `namespace` | string | **是** | 入口类所在命名空间；入口类为 `{namespace}\Plugin`。留空则核心不会调用 `register()`（只能靠 `register.php`） |
| `hooks` | string[] | 否 | 仅用于声明与后台展示，**不参与加载逻辑**，但建议与实际注册保持一致 |
| `assets.css` / `assets.js` | string[] | 否 | 相对插件目录的资源路径 |
| `settings` | object / array | 否 | 插件配置项声明，见第七节 |
| `requires` | string | 否 | 要求的最低核心版本，默认 `1.0.0` |

**插件 ID = 目录名**，必须匹配 `/^[a-z0-9][a-z0-9_\-]{0,31}$/`。不满足的目录会被直接忽略并写警告日志。

## 四、生命周期

```
discover()          扫描 plugins/*/plugin.json，校验 ID 与清单
      ↓
syncDatabase()      与 plugins 表对齐：
                    · 新插件 => 写入记录，enabled = 0（必须由管理员显式启用）
                    · 已有插件 => 同步 name/version/description/author/url/hooks
                    · 磁盘上已消失 => enabled 置 0（保留数据，便于恢复）
      ↓
loadEnabled()       对每个已启用插件：
                    · safePath() 校验入口文件路径（硬阻断目录穿越）后 require_once
                    · 若 {namespace}\Plugin 存在且有 register() => 调用
                    · 若存在 register.php => 一并 require
                    · 记录 loaded，触发 plugin_loaded 钩子
      ↓
loadPluginRoutes()  把插件注册的路由追加进路由表（核心路由优先）
      ↓
mergeAssets()       合并插件 CSS/JS（仅在文件 mtime 变化时重建）
```

**后台动作**

| 动作 | 行为 |
| --- | --- |
| 启用 | 执行 `sql/{driver}.sql` 建表 → `enabled = 1` → 加载插件 → 重建资源合并 → 同步计划任务 |
| 停用 | `enabled = 0`（**保留配置与数据**）→ 重建资源合并 → 同步计划任务 |
| 卸载 | 删除 `plugins` 表记录与 `cron_tasks` 中该插件的任务 |

> ⚠️ 卸载**不会**删除插件目录，也**不会**删除插件自建的表。需要彻底清理时请手动处理。

## 五、`Core\Plugin` 门面 API

插件只应通过这个门面与核心交互，不要直接操作核心内部状态。

```php
use Core\Plugin as PluginApi;
```

| 方法 | 说明 |
| --- | --- |
| `filter(string $name, callable $cb, int $priority = 10)` | 注册 filter 钩子 |
| `action(string $name, callable $cb, int $priority = 10)` | 注册 action 钩子 |
| `route(string $method, string $path, callable\|string $handler, string $permission = '')` | 注册路由 |
| `adminPage(string $slug, string $title, callable\|string $handler, string $permission = 'admin.access', string $icon = '')` | 注册后台页面 `/admin/plugin/{slug}` |
| `menu(string $title, string $url, string $icon = '')` | 注册前台导航项 |
| `cron(string $name, int $interval, callable\|string $handler)` | 注册计划任务（`interval` 最小 60 秒） |
| `config(array $defaults = [], ?string $pluginId = null)` | 读取配置（与默认值合并） |
| `saveConfig(array $config, ?string $pluginId = null)` | 写入配置（合并写入） |
| `tableName(string $suffix, ?string $pluginId = null)` | 推导自建表名 |
| `table(string $suffix, ?string $pluginId = null)` | 获取自建表的查询构造器 |
| `path(string $relative = '', ?string $pluginId = null)` | 插件目录内的绝对路径 |
| `asset(string $relative, ?string $pluginId = null)` | 生成插件资源 URL |
| `log(string $message, array $context = [])` | 写插件日志 |

> ⚠️ **最容易踩的坑**：`Plugin::$current` 只在「加载阶段」有值。请求分发阶段的代码（钩子回调、处理器）**必须显式传入插件 ID**：
>
> ```php
> // 正确
> PluginApi::config(self::DEFAULTS, 'my-plugin');
> PluginApi::table('activity', 'my-plugin');
>
> // 错误：加载期之外 $current 为空串，会读不到任何配置
> PluginApi::config(self::DEFAULTS);
> ```
>
> 建议在插件入口类里定义 `public const ID = 'my-plugin';` 并统一引用。

## 六、钩子

### 6.1 两种钩子

```php
// filter：有返回值，沿链传递（必须返回处理后的值，否则后续监听者拿到 null）
PluginApi::filter('content_rendered', function (string $html, array $context): string {
    return $html . $context['suffix'];
});

// action：忽略返回值，只关心「发生了什么」
PluginApi::action('after_post_create', function (array $context): void {
    // $context['post_id']、$context['thread_id'] ...
});
```

`$priority` 数值越小越先执行，同优先级保持注册顺序。

**异常策略**：`Core\Hook::filter()` 会隔离回调抛出的普通异常并写日志（插件缺陷不会拖垮整站），
但 `HttpException` 会向上冒泡。因此**拦截类钩子**（`before_*`）必须用以下方式中断流程：

```php
// 方式一：直接终止，交由核心渲染错误页（AJAX 请求自动返回 JSON）
\Core\App::abort(403, '不允许发布该内容。');

// 方式二：更友好 —— 回填内容并跳回来源页
\Core\Session::setErrors(['content' => $message]);
\Core\Session::flashInput(\Core\Request::allPost());
\Core\Session::setFlash('message', $message);
\Core\Session::setFlash('type', 'error');
\Core\Response::redirect(\Core\Request::referer() ?: \Core\Router::url('/'));
```

抛普通异常**不会**阻止流程。

### 6.2 钩子总表

与 `Core\Hook::DEFINED` 一一对应，`context` 列为回调可读取的上下文键。

#### 生命周期

| 钩子 | 类型 | 触发时机 | context |
| --- | --- | --- | --- |
| `app_boot` | action | 应用启动完成（会话、设置、插件、路由均已就绪） | `app` |
| `app_before_dispatch` | action | 路由分发前 | `path`、`route` |
| `app_after_dispatch` | action | 路由分发后 | `path`、`route` |
| `plugin_loaded` | action | 单个插件加载完成 | `plugin` |

#### 资源与导航

| 钩子 | 类型 | 触发时机 | context |
| --- | --- | --- | --- |
| `head_assets` | filter | 在 `<head>` 内追加 HTML（前台与后台布局都会触发） | — |
| `footer_assets` | filter | 在 `</body>` 前追加 HTML | — |
| `nav_links` | filter | 前台顶部导航附加链接数组 | `user` |
| `admin_nav_links` | filter | 后台侧栏导航链接数组 | `user` |
| `user_profile_tabs` | filter | 用户中心标签页数组 | `profile`、`active` |
| `thread_view_actions` | filter | 主题详情页操作区 HTML | `thread`、`forum`、`user` |

`nav_links` 的数组元素结构：

```php
['label' => '文案', 'url' => '/hello', 'icon' => 'bulb']   // icon 取 values 中不存在的名字时自动退化为圆点
```

`user_profile_tabs` 的数组元素结构：

```php
['key' => '唯一键', 'label' => '文案', 'url' => '/u/1/xxx']
```

> ⚠️ `nav_links` 与 `user_profile_tabs` 的 `url` 都会经过 `url()` 处理，因此：
> - 传**站内路径**（如 `/hello/1`），不要传已经拼好的完整地址
> - **不要带查询串**（`?a=1`）。需要参数时请改用 `url($path, $params)` 在模板中自行生成，
>   或把参数编进路径（如 `/hello/{name}`）
>
> 需要生成可在子目录部署与 `?r=` 兼容形态下都正确的地址时，一律使用 `Router::url($path, $params)`。

`head_assets` / `footer_assets` / `thread_view_actions` 的返回值会**原样输出为 HTML**，
插件必须自行保证转义（用 `e()`）。

#### 内容与列表

| 钩子 | 类型 | 触发时机 | context |
| --- | --- | --- | --- |
| `content_render` | filter | 正文**入库前**的原文过滤 | `user`、`forum`、`thread` |
| `content_rendered` | filter | 正文**渲染后**的 HTML 过滤（输出时） | `raw` |
| `forum_list` | filter | 首页版块列表 | `user` |
| `thread_list` | filter | 版块内主题列表 | `forum` |
| `post_list` | filter | 主题内回帖列表 | `thread` |

#### 主题

| 钩子 | 类型 | 触发时机 | context |
| --- | --- | --- | --- |
| `before_thread_create` | action | 发表主题前（可拦截） | `user`、`forum`、`title`、`content` |
| `after_thread_create` | action | 发表主题后 | `user`、`forum`、`thread_id`、`post_id` |
| `after_thread_update` | action | 编辑主题后 | `thread_id`、`user` |
| `after_thread_delete` | action | 删除主题后 | `thread_id`、`user` |

#### 回帖

| 钩子 | 类型 | 触发时机 | context |
| --- | --- | --- | --- |
| `before_post_create` | action | 发表回复前（可拦截） | `user`、`thread`、`forum`、`content` |
| `after_post_create` | action | 发表回复后（**待审核的回复不触发**） | `user`、`thread_id`、`post_id`、`floor` |
| `after_post_delete` | action | 删除回复后 | `post_id`、`user` |

#### 用户

| 钩子 | 类型 | 触发时机 | context |
| --- | --- | --- | --- |
| `before_user_register` | action | 注册前（可拦截，如邀请码校验） | `username`、`email` |
| `after_user_register` | action | 注册后（此时已自动登录） | `user_id`、`username` |
| `after_user_login` | action | 登录成功后 | `user_id` |
| `after_user_logout` | action | 退出登录后 | `user_id` |
| `after_profile_update` | action | 修改资料后 | `user_id` |
| `after_password_change` | action | 修改密码后 | `user_id` |
| `after_avatar_upload` | action | 上传头像后 | `user_id`、`path` |

> 钩子名会被规范化为小写并把非字母数字字符转成下划线，因此 `beforeThreadCreate` 与 `before_thread_create` 等价。
> 但**注册与触发必须拼写一致**，否则会静默失效，建议直接复制上表。

## 七、插件配置

在清单中声明，后台「插件管理 → 配置」自动生成表单：

```json
"settings": {
    "greeting": {
        "label": "问候语",
        "type": "text",
        "default": "你好",
        "hint": "展示在插件页面顶部"
    },
    "style": {
        "label": "页面样式",
        "type": "select",
        "default": "card",
        "options": { "card": "卡片式", "plain": "极简式" }
    },
    "enabled_flag": { "label": "启用某功能", "type": "checkbox", "default": "1" },
    "days": { "label": "保留天数", "type": "number", "default": "7" },
    "raw": { "label": "自定义文本", "type": "textarea", "default": "" }
}
```

- 键名必须匹配 `/^[a-z0-9_]{1,40}$/`
- `type` ∈ `text` / `textarea` / `checkbox` / `select` / `number`
- 保存时**只保存清单里声明过的键**，插件无法借此写入任意数据
- `checkbox` 存为 `'1'` / `'0'` 字符串
- `select` 只接受 `options` 中声明过的键，非法值回落到 `default`
- 单个字段最长 2000 字符

读取时务必给出默认值兜底，并显式传入插件 ID：

```php
private const DEFAULTS = ['greeting' => '你好', 'style' => 'card'];

$config = PluginApi::config(self::DEFAULTS, Plugin::ID);
$greeting = (string)($config['greeting'] ?? self::DEFAULTS['greeting']);
```

## 八、插件自建数据表

### 表名规则

```
plugin_{插件ID规范化}_{后缀}
```

规范化：转小写 → 短横线转下划线 → 剔除非 `[a-z0-9_]` 字符。

| 插件 ID | 后缀 | 表名 |
| --- | --- | --- |
| `owlsgo-demo` | `activity` | `plugin_owlsgo_demo_activity` |
| `seo_tools` | `meta` | `plugin_seo_tools_meta` |

建表脚本里的表名必须与 `Plugin::tableName('activity')` 推导结果**完全一致**，否则表建好了插件却读不到。

### 建表脚本

放在 `sql/sqlite.sql`、`sql/mysql.sql`、`sql/pgsql.sql`，**仅在「启用插件」时**按 `Database::driver()` 执行。

执行规则（`PluginManager::splitStatements()`）：

- 按「以分号结尾的行」切分语句，因此一条 `CREATE TABLE` 可以跨多行
- 以 `--` 或 `#` 开头的行会被跳过（注释可用）
- 不支持存储过程、触发器、`DELIMITER`
- 单条语句失败只记日志、不中断，其余语句继续执行

```sql
-- sql/sqlite.sql
CREATE TABLE IF NOT EXISTS "plugin_owlsgo_demo_activity" (
    "id"         INTEGER PRIMARY KEY AUTOINCREMENT,
    "user_id"    INTEGER NOT NULL DEFAULT 0,
    "created_at" INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS "idx_plugin_owlsgo_demo_activity_created"
    ON "plugin_owlsgo_demo_activity" ("created_at");
```

> 改了表结构后需要**停用再重新启用**插件才会重新执行建表脚本。
> 脚本一律使用 `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS`，保证重复执行安全。

### 读写

```php
use Core\Plugin as PluginApi;

PluginApi::table('activity', Plugin::ID)->insert([
    'user_id'    => 3,
    'created_at' => time(),
]);

$rows = PluginApi::table('activity', Plugin::ID)
    ->where('user_id', 3)
    ->orderBy('id', 'desc')
    ->limit(20)
    ->get();

$count = PluginApi::table('activity', Plugin::ID)->count();
```

`Plugin::table()` 返回 `Core\Query`，所有条件都使用占位符绑定，不要自己拼 SQL。

## 九、路由

```php
PluginApi::route('GET', '/hello', 'MyPlugin\\HelloController@index');
PluginApi::route('GET', '/hello/{name}', 'MyPlugin\\HelloController@greet');
PluginApi::route('POST', '/hello/clear', 'MyPlugin\\HelloController@clear', 'admin.access');
```

- **路径占位符**：`{name}`（默认 `[^/]+`）或 `{id:\d+}`（自定义正则），匹配结果以 `$params` 数组传给处理器
- **处理器写法**：`'命名空间\类@方法'` 字符串（核心会实例化控制器），或闭包 `fn (array $params) => string`

> ⚠️ 控制器处理器**必须**用 `"Class@method"` 字符串形式。
> 传 `[类名, 方法名]` 数组会被当成静态调用，非静态方法在 PHP 8 下会直接报错。

- **CSRF**：插件路由的写方法（POST/PUT/PATCH/DELETE）**始终强制校验**，表单里必须输出 `csrf_field()`
- **权限**：第 4 个参数填 `Core\Permission::CATALOG` 中的权限标识。留空表示**不做任何校验，也不校验登录**；
  需要「仅登录可见」时，要么填一个游客组没有的权限（如 `attachment.upload`），要么在处理器里调用 `Auth::requireLogin()`
- **优先级**：核心路由先注册、插件路由后注册。路径与核心**完全相同**时核心优先，插件路由永远不会命中，请避开核心路径

可用权限标识（`Core\Permission::CATALOG`）：

```
thread.view  thread.create  thread.reply  thread.edit  thread.essence
thread.delete  post.delete  post.approve  attachment.upload  attachment.manage
user.ban  user.manage
admin.access  admin.settings  admin.forum  admin.group  admin.user
admin.content  admin.plugin  admin.cron  admin.logs
```

## 十、后台页面

```php
PluginApi::adminPage('my-plugin', '我的插件', 'MyPlugin\\AdminController@admin', 'admin.access', 'puzzle');
```

- 访问地址：`/admin/plugin/{slug}`（`slug` 会被规范化为 `[a-z0-9_-]`）
- 该路由由核心固定要求 `admin.access`，`adminPage()` 的权限参数用于控制后台侧栏中是否显示入口
- 处理器返回**非空字符串**时作为整页 HTML 输出；返回空值或非字符串时核心渲染占位页

**推荐做法：继承后台基类以复用后台布局与侧栏导航。**

```php
namespace MyPlugin;

use Modules\Admin\AdminBaseController;

final class AdminController extends AdminBaseController
{
    public function admin(array $params): string
    {
        return $this->adminView('plugin/my-plugin/admin', [
            'pageTitle'  => '我的插件 - ' . (string)setting('site_name'),
            'adminTitle' => '我的插件',
            'records'    => Service::recent(30),
        ]);
    }
}
```

`adminView()` 会自动注入 `adminNav`（已按权限过滤 + 插件页面）、`adminTitle`、`adminSubtitle`，
并套用 `layouts/admin`。

## 十一、前台导航菜单

```php
PluginApi::menu('我的功能', Router::url('/my-page'), 'layers');
```

菜单项由核心渲染到前台顶部导航。`$url` 请使用 `Router::url(...)` 生成，
这样在子目录部署与 `index.php?r=` 兼容形态下都能正确工作。
模板只渲染以 `/` 或 `http(s)://` 开头的地址，其它会被忽略。

需要更动态的控制（例如仅登录用户可见）时，改用 `nav_links` 钩子。

## 十二、计划任务

```php
PluginApi::cron('my_cleanup', 86400, 'MyPlugin\\Service@cleanup');
```

- `$interval` 为秒，**最小 60**
- 处理器可写 `"Class@method"` 字符串（方法须为 `static`）或闭包；**不接受必填参数**
- 任务登记进 `cron_tasks` 表的时机是**插件启用 / 停用时**的 `syncCronTasks()`。
  给已启用的插件新增任务后，需要**停用再启用**一次才会入库。
- 触发方式：
  1. 后台「计划任务 → 立即执行」
  2. 外部定时器访问 `GET /cron/run?token=xxx`（令牌在后台生成，可重置）
- 每次执行都会写入 `cron_logs`，可在后台查看
- 处理器内部应自行捕获异常并返回，避免依赖外部重试

## 十三、静态资源

在清单中声明，核心会把所有已启用插件的资源**合并成单文件**，减少请求数：

```json
"assets": {
    "css": ["assets/plugin.css"],
    "js": ["assets/plugin.js"]
}
```

- 输出地址：`/plugin-assets/css`、`/plugin-assets/js`
- 合并结果写入 `storage/cache/plugins.css|js`，**仅在源文件 mtime 变化时重建**
- 响应头：`Cache-Control: public, max-age=3600`（因为文件名固定，不能长期强缓存）
- CSS 中的 `@import` 会被自动剥离（禁止引入远程资源）
- 前台主布局与后台布局都会自动引入合并资源，插件无需手动加 `<link>`

单个文件也可以直接访问：

```php
PluginApi::asset('assets/logo.svg');   // => /plugin-file/my-plugin/assets/logo.svg
```

扩展名白名单：`css js mjs map json png jpg jpeg gif webp ico svg woff woff2 ttf otf txt md`。

> `.php` 以及任何不在白名单内的类型一律返回 403，绝不会被当作脚本执行。
> `.svg` 会额外带上 `Content-Security-Policy: ... sandbox`。
> 所有路径都经过 `PluginManager::safePath()` 的 realpath 校验，无法越出插件目录。

## 十四、插件自带模板

模板放在 `plugins/{id}/templates/`，通过命名空间前缀渲染：

```php
// 套用默认前台布局（layouts/main）
return $this->view('plugin/my-plugin/hello', ['greeting' => '你好']);

// 指定布局
return \Core\View::render('plugin/my-plugin/hello', $data, 'layouts/admin');

// 不套布局
return \Core\View::render('plugin/my-plugin/fragment', $data, '');
```

- 渲染时同样会注入 `$view` 闭包与全部默认变量（`currentUser`、`currentPath`、`siteName`、`flashMessage`、`pageTitle` 等）
- 可以直接调用核心局部模板：`$view('partials/icon', ['name' => 'bulb'])`、`$view('partials/flash')`
- 插件 ID 与模板名都会做白名单校验，且 `realpath` 必须落在插件目录内，无法越界读文件

## 十五、安全红线

**必须遵守**

1. 所有输出到 HTML 的动态内容都经过 `e()` 转义
2. 所有数据库操作使用 `Core\Query` 或占位符绑定，禁止拼接 SQL
3. 写操作只暴露为 POST 路由，并在表单中输出 `csrf_field()`
4. 路由与后台页面显式声明权限；不要用「留空权限」来表达「需要登录」
5. 插件配置、密钥、令牌一律通过 `Plugin::config()` 存取，不要硬编码
6. 在 `register()` 中只做注册；数据库查询留给钩子回调与处理器
7. 钩子回调要快、要容错：查库失败要 catch 并记日志，不能影响主流程
8. 业务逻辑放在插件的 Model/Service 层，不要把 SQL 写进模板

**禁止**

1. 修改 `core/`、`modules/`、`templates/` 下的核心文件
2. 直接操作 `$_SESSION`、`$_POST`，或绕过 `Core\Request` / `Core\Session`
3. 在插件目录放置 `.php` 并期望通过 URL 直接访问（会被 403 拒绝）
4. 用 `eval()`、`extract()`、动态 `include` 处理用户输入
5. 在钩子里做长时间阻塞操作（远程请求、大文件处理），这类逻辑应放进计划任务

## 十六、常见问题与排错

| 现象 | 原因与处理 |
| --- | --- |
| 后台插件列表里没有我的插件 | 目录名不合法；或缺少 `plugin.json`；或 JSON 解析失败。查看 `storage/logs/` 下的日志 |
| 插件显示「未启用」但明明点过启用 | 新发现的插件默认 `enabled = 0`，需要手动点「启用」 |
| 钩子注册了却完全不执行 | 钩子名拼写与核心不一致（对照第 6.2 节总表）；或插件未启用；或缓存了旧的 `storage/cache/plugins.*` |
| 读不到插件配置，拿到的全是默认值 | `Plugin::config()` 没传插件 ID。加载期之外 `Plugin::$current` 为空 |
| `class_exists` 找不到我的类 | 插件命名空间不在核心自动加载器范围内，需在入口文件里 `spl_autoload_register`（见示例插件） |
| 路由 404 | 插件未启用；或路径被核心路由优先匹配；或路径写成了无前导斜杠形式 |
| 接口报 419 | 表单缺少 `csrf_field()`。插件路由的写方法强制校验 CSRF |
| 建表失败 / 表不存在 | 表名与 `Plugin::tableName()` 推导不一致；或未停用再启用；查看日志中 `plugin-install:` 前缀的异常 |
| 计划任务不执行 | 新增任务后未停用再启用；或 `next_run_at` 还没到；或在计划任务页手动触发验证 |
| 资源 404 或 403 | 清单里的路径写错；或扩展名不在白名单；或插件未启用（合并资源不会包含它） |
| 拦截发帖没生效 | 用了 `throw new \Exception()`。普通异常会被隔离，必须用 `App::abort()` 或 `Response::redirect()` |
| 插件页面白屏 | 后台页处理器返回了空值，核心此时会渲染占位页；前台页请检查模板路径与 `view()` 参数 |

**调试建议**

- 用 `PluginApi::log('...', ['key' => $value])` 写结构化日志，不要用 `var_dump` / `echo`
- 关闭插件只需在后台点「停用」，配置与数据都会保留
- 修改插件模板或资源后无需清缓存；修改 `plugin.json` 的元数据会在下次请求自动同步
- 合并资源出现异常时，删除 `storage/cache/plugins.css|js` 与 `storage/cache/.signature` 可强制重建
